## Шаги

Порядок обязателен: контракт раньше кода, тест раньше реализации, домен раньше
транспорта, story раньше API. Каждый шаг — с конкретными путями файлов, а не
«добавить логику».

### Ш1. Миграция

`make migrate-create name=…` — какие таблицы и колонки, какие ограничения.

### Ш2. Запросы и репозиторий

`internal/db/queries/*.sql` (sqlc) → `make generate` → адаптер в
`internal/repository/<агрегат>/`: какие сущности отдаёт наружу, какие ошибки драйвера
переводит в доменные.

### Ш3. Спека API

`docs/api/openapi.yaml`: операции, коды ответов, схемы. Затем `make generate`.

### Ш4. Домен

`internal/service/entity/` — инвариант; `internal/service/usecase/<операция>/`
(`usecase.go` + `contracts.go`) — сценарий и его зависимости; `service/errors` —
ожидаемые исходы. Внутри шага: сигнатуры заглушками → тест на каждый исход →
`make red` → реализация (скилл `/tdd`).

### Ш5. Транспорт

`internal/httptransport/` + `schemas/`: маппинг и соответствие «доменная ошибка → код
ответа». Бизнес-логики здесь нет. Кейсы на коды ответов пишутся до хендлера — так же,
как в Ш4.

### Ш6. Фронт: макет на моках (story-first)

Токены в `DESIGN.md` → `make generate` → компонент из `front/src/design-system/` +
story, визуальная проверка скриншотом через browser MCP.

### Ш7. Фронт: подключение

Типизированный клиент `front/src/api/client.ts` поверх `front/src/gen/api.d.ts`.

### Ш8. Реестр и сдача

Строка этапа в `docs/plans/README.md`, ADR на нетривиальные решения и маркеры
`// ADR:` в коде, зелёный `make verify`.

## Тесты

Тест — часть шага, а не работа «в конце»: он пишется до реализации и задаёт её
поведение (ADR `docs/adr/0008-testy-kak-specifikaciya.md`).

- Домен: `internal/service/usecase/<операция>/usecase_test.go` — на моках, по кейсу
  на каждый исход операции.
- Транспорт: `internal/httptransport/handlers_test.go` — по кейсу на каждый код
  ответа из спеки.
- Перечислить здесь ожидаемое поведение словами: «пустое имя → ошибка валидации»,
  «дубль имени → 409». Это формулировки будущих кейсов, и по ним же видно, что в
  спеке ещё не определено.
