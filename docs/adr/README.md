# ADR — Architecture Decision Records

План этапа и тесты отвечают на вопрос **«что»**.
ADR отвечает на вопрос **«почему именно так»**: фиксирует контекст, рассмотренные
альтернативы и причину выбора. Это долговременный результат связки *план →
реализация*: план обсуждается и устаревает, код показывает «как», а ADR
сохраняет «почему» — чтобы спустя месяцы не переоткрывать уже закрытые вопросы.

## Когда писать ADR

Заводи ADR на каждое нетривиальное решение, которое не видно из самого кода:
выбор схемы данных, формы API, границы слоёв, внешней зависимости, компромисса
производительность/простота. Не нужен ADR на механические правки и на то, что
очевидно из названия метода.

## Формат

- Файлы: `docs/adr/NNNN-kratkiy-zagolovok.md`, `NNNN` — сквозной номер с нуля
  (`0001`, `0002`, ...). Номер не переиспользуется.
- Шаблон — `0000-template.md`. Скопируй его, присвой следующий свободный номер.
- ADR неизменяем по сути: решение пересмотрели — заводи новый ADR и проставь в
  старом `Статус: заменён ADR-NNNN`, а в новом — `Заменяет ADR-NNNN`.
- Все ADR пишутся на русском.

## Связь с кодом

Каждое место в коде, реализующее решение из ADR, помечается комментарием со
ссылкой на файл ADR — чтобы из кода было видно, где искать контекст «почему»:

```go
// ADR: docs/adr/0009-cli-bez-demona.md — резидентный процесс один, сам Chrome
package main
```

Маркер всегда начинается с `ADR:` и содержит путь к файлу — так его легко найти
grep'ом (`grep -rn "ADR:" cmd/ internal/`) и кликнуть из IDE. Обратная ссылка (из ADR
в код) — в разделе «Где в коде» самого ADR.

## Связь с планами

План (`docs/plans/`) обсуждает и проектирует решение, ADR фиксирует итог («что» и
«почему»). Когда план реализован и решение нетривиально — заводи ADR и проставь
перекрёстные ссылки: в ADR — «Связано: план `docs/plans/...`», в плане сверху —
указатель на итоговый ADR. План со временем устаревает, ADR остаётся.

## Отложенные удаления

Рядом лежит `DEPRECATIONS.md` — реестр того, что подлежит удалению позже. Прод едет
только вперёд, изменения обратно совместимы (expand/contract): новое вводится, не
ломая старое, а удаление старого выносится в отдельный отслеживаемый шаг. ADR
объясняет «почему так решили», реестр — «что из-за этого ещё предстоит снести».
