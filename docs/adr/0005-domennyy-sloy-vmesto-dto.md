# 0005. Доменный слой с сущностями и операциями вместо каталога dto

- **Статус:** принято
- **Дата:** 2026-08-19
- **Заменяет:** ADR-0001
- **Связано:** `internal/service/**`, `internal/repository/**`,
  `internal/httptransport/**`

## Контекст

ADR-0001 ввёл `internal/dto` — каталог чистых структур без логики — и связку
`handler → store → gen/db`. Пока сервис только читал и писал строки, этого хватало.
Как только появляются правила («имя не пустое», «имя короче 255», «повтор — конфликт,
а не сбой»), их некуда положить: структура без логики их не удержит, и они оседают
в хендлере. Хендлер, который проверяет инварианты, обходится любым вторым входом —
воркером, консьюмером, второй ручкой, — и правило перестаёт быть правилом.

## Решение

Домен живёт в `internal/service`:

- `entity/` — сущности с приватными полями; корректный объект создаётся только
  конструктором (`entity.NewItem`), инвариант проверяется там;
- `errors/` — доменные ошибки (`ErrNotFound`, `ErrConflict`, `ValidationError`);
- `ports/` — интерфейсы адаптеров глазами домена;
- `usecase/<операция>/` — одна операция = один пакет: `usecase.go` с реализацией и
  `contracts.go` с интерфейсами зависимостей ровно той ширины, что нужна операции.

`internal/repository/<агрегат>` возвращает сущности и переводит ошибки драйвера
в доменные; `internal/httptransport` только маппит, а соответствие «доменная ошибка →
код ответа» собрано в `httptransport/schemas`.

## Почему именно так

Рассматривали три варианта. (1) Оставить dto и валидировать в хендлере — дёшево,
но правило дублируется на каждом входе и рано или поздно расходится. (2) Один общий
пакет `service` со всеми операциями — быстро превращается в файл на тысячу строк,
где зависимости операции неотличимы от зависимостей соседней. (3) Пакет на операцию
с собственным `contracts.go` — больше файлов, зато видно, от чего операция зависит,
и в тесте подменяется один метод, а не весь репозиторий. Выбран третий: цена —
несколько лишних файлов, выгода — границы, которые проверяет компилятор и `depguard`.

Сущность заменяет dto полностью: транспортно-независимый центр остался, но теперь
он умеет защищать себя сам.

## Последствия

- Проще: правило существует в одном месте; тест операции не требует БД; новый вход
  (воркер, вторая ручка) не может обойти инвариант.
- Сложнее: на операцию заводится пакет; между строкой БД и сущностью появляется
  маппер; для моков нужен mockery.
- `internal/dto`, `internal/store`, `internal/handler` удалены, ADR-0001 заменён.

## Где в коде

`internal/service/entity/item.go`, `internal/service/usecase/createitem/`,
`internal/repository/item/repository.go`, `internal/httptransport/schemas/item.go`.
