- **Дата:** 2026-06-19
- **Связано:** `front/src/design-system/`, `DESIGN.md`, `CLAUDE.md`,
  `.claude/skills/add-component/SKILL.md`, заменяет [[0003-dizayn-kit-primitivov]],

## Контекст

ADR-0003 ввёл «дизайн-кит» — плоский набор примитивов в `front/src/components/kit/`.
По мере роста UI плоского кита мало: повторяющиеся композиции (поле формы с подписью и
ошибкой) и структурная разметка (стопки, контейнеры) собирались бы заново в каждом
бизнес-компоненте, дублируя логику и расходясь в отступах. Нужна не «коллекция
примитивов», а дизайн-система с явными слоями: где атом, где композиция, где структура.

## Решение

Кит превращается в дизайн-систему — `front/src/design-system/` с реэкспортом через
корневой `index.ts` (`export *` по слоям). Три слоя:

- **`primitives/`** — атомы (Button, Input, Card, Badge, Checkbox, Select, Spinner),
  перенесены из бывшего `components/kit/`. Реализация секции `components` контракта.
- **`patterns/`** — композиции примитивов под повторяющиеся задачи (FormField).
- **`layout/`** — структурные примитивы на токенах `spacing`, без цвета (Stack, Container).

Правило (CLAUDE.md, DESIGN.md): дизайн всегда содержит дизайн-систему; любой UI
композится из её слоёв, а не из голых утилит/хардкода. Story-id — `Design System/<Слой>/<Name>`.
Бизнес-компоненты (`front/src/components/`) импортируют систему из `../design-system`.

## Почему именно так

- **Слои против плоского кита**: явная граница «атом → композиция → структура» убирает
  дублирование композиций и отступов по бизнес-компонентам; новый компонент сразу
  попадает в нужный слой, а не сваливается в общую кучу.
- **Один barrel**: корневой `index.ts` реэкспортит слои (`export *`), потребитель пишет
  `import { Card, FormField, Stack } from '../design-system'` без знания внутренней
  раскладки.
- **Layout на токенах spacing**: Stack/Container задают ритм через `gap-tight`/`px-card`,
  а не произвольные значения — отступы тоже под контрактом `DESIGN.md`.
- **Отдельный каталог `design-system/`** вместо `components/kit/`: система — не «ещё
  одна папка компонентов», а самостоятельный слой рядом с бизнес-компонентами.

## Последствия

Плюс: масштабируемая структура, единая точка импорта, отступы под контрактом. Минус:
у системы нет выделенного danger-цвета (палитра одноакцентная) — ошибка в FormField
красится `primary`, согласованно с invalid-границей Input; при необходимости явного
красного добавляется токен в `DESIGN.md`. `design-guard` теперь грепает и
`front/src/design-system/`, и `front/src/components/`.

## Где в коде

- `front/src/design-system/` — слои `primitives/`, `patterns/`, `layout/` и `index.ts`
  (помечены `ADR:`).
- `front/src/components/ExampleCard.vue` — образец композиции из системы.
- `Makefile` (`design-guard`) — запрет hex по обоим каталогам.
- Скилл `/add-component` — процедура добавления компонента в слой.
