# Новый ADR

## Когда нужен

Когда выбор неочевиден: два рабочих варианта, компромисс, отказ от привычного
подхода, внешнее ограничение. Очевидное не документируется — шум обесценивает реестр.
Механические правки ADR не требуют.

## Как завести

1. Следующий свободный номер: `ls docs/adr/`. Номера не переиспользуются.
2. Файл `docs/adr/NNNN-kratkiy-zagolovok.md` по шаблону `0000-template.md`.
3. Разделы: Контекст → Решение → Почему именно так → Последствия → Где в коде.
   В «Почему» назови отвергнутые варианты и их цену — без этого ADR не отвечает
   на вопрос, ради которого пишется.
4. В затронутом коде — маркер `// ADR: docs/adr/NNNN-....md — короткое почему`
   (ищется `grep -rn "ADR:" internal/`).

## Пересмотр решения

ADR не переписывается. Заводится новый со ссылкой `Заменяет ADR-NNNN`, а в старом
меняется только строка статуса на `заменён ADR-NNNN` (образец — ADR-0001 и ADR-0005).

## Отложенные удаления

Что нужно снести позже — в `docs/adr/DEPRECATIONS.md` с проверяемым условием
(дата, версия, «после backfill NNNNNN»), в коде — `// DEPRECATED: ...`.

Все ADR на русском.
