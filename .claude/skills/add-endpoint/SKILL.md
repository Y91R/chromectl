# Новый API-эндпоинт

Строго в этом порядке, не пропуская шаги. Код, написанный до генерации, будет затёрт.

1. **Спека**: добавь эндпоинт в `docs/api/openapi.yaml` (operationId, схемы запросов и
   **каждый** код ответа, включая ошибочные — через существующие
   `components/responses/*`). Согласуй с пользователем, если форма API неочевидна.
   Изменение существующего контракта — обратно совместимое (новые поля опциональны,
   старые не удаляй и не переименовывай). Несовместимое — только через новую
   ручку/версию; старую помечай `// DEPRECATED:` и заноси в `docs/adr/DEPRECATIONS.md`.
2. **Генерация**: `make generate`. В `gen/api/generated.go` появятся методы
   `StrictServerInterface`, в `front/src/gen/api.d.ts` — TS-типы. `gen/` руками не трогать.
3. **Домен**: бизнес-правило эндпоинта — не в хендлере. Инвариант живёт в
   `internal/service/entity/`, сценарий — в `internal/service/usecase/<операция>/`
   (скилл `/add-usecase`). Если операция уже есть — переходи к следующему шагу.
4. **Данные (если нужны)**: миграция через `make migrate-create name=...` (скилл
   `/add-migration`), запросы в `internal/db/queries/*.sql`, `make generate`, затем
   метод репозитория в `internal/repository/<агрегат>/`. Репозиторий возвращает
   **сущности**, а ошибки драйвера переводит в доменные (`ErrNotFound`, `ErrConflict`).
5. **Тест — до хендлера** (скилл `/tdd`): объяви метод интерфейса заглушкой (пустой
   ответ + `errors.New("не реализовано")`), чтобы код собирался, и напиши кейс на
   **каждый** код ответа из спеки (образец — `internal/httptransport/handlers_test.go`;
   операции подменяются моками из `gen/mocks/service/usecase/...`, БД и сеть не нужны).
   Ожидания берутся из спеки, а не из кода: тип ответа `api.<Operation><Код>...` и
   тело — литералом. Убедись, что тест красный: `make red RUN=TestCreateItem_409`.
   Тест после хендлера зафиксировал бы фактическое поведение вместе с его багами.
6. **Транспорт**: реализуй метод в `internal/httptransport/handlers.go` — только
   распаковка запроса, вызов операции и упаковка ответа. Соответствие
   «доменная ошибка → код ответа» и маппинг сущность → модель контракта живут
   в `internal/httptransport/schemas/` (образец — `CreateItemError`, `ToItem`).
   Неизвестная ошибка возвращается наверх как `error`: превращать её в 4xx нельзя.
   Позеленело — сломай маппинг намеренно (верни не тот код) и проверь, что падает
   именно тот кейс; затем верни код.
7. **ADR (если решение нетривиально)**: неочевидная форма API, граница слоёв,
   компромисс — `docs/adr/NNNN-zagolovok.md` по шаблону `0000-template.md`
   (скилл `/new-adr`), в коде маркер `// ADR: docs/adr/NNNN-....md`.
8. **Проверка**: `make verify` (generate-check + lint + guard + test-guard + test +
   design-guard), сгенерированные файлы закоммичены вместе с контрактом, который их
   породил.

Эндпоинт готов, только когда на каждый код ответа из спеки есть тест, написанный до
хендлера, — непокрытый код ответа валит `make test-guard`.
