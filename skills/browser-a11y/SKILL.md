# Доступность через chromectl

Команды — из скилла `/chromectl:browser` (там же правила запуска: Chrome только вне песочницы
Bash). Сниппеты для `eval` — в [references/a11y-snippets.md](references/a11y-snippets.md).

**Дерево доступности, а не DOM.** Спрятанный через `opacity: 0` элемент для скринридера
остаётся, а `display: none` и `aria-hidden="true"` — нет. `chromectl snapshot` печатает
именно дерево доступности, то, что «видят» вспомогательные технологии, — это главный
источник правды о семантике.

**Документация web.dev.** К адресу статьи (например,
`https://web.dev/articles/accessible-tap-targets`) можно добавить `.md.txt` и получить
чистый markdown.

## Порядок работы

### 1. Автоматический аудит (Lighthouse)

```bash
chromectl audit lighthouse --output-dir /tmp/lh
```

- Оценки печатаются от 0 до 100: меньше 100 в `accessibility` — есть нарушения;
  `аудитов: не пройдено N` — сколько.
- Отчёт не читай целиком — вытащи только проваленные аудиты:

  ```bash
  jq -c '.audits[] | select(.score != null and .score < 1) | {id, title, items: .details.items}' /tmp/lh/report.json
  ```

  Так видны `selector` и `snippet` проблемных элементов без всего отчёта в контексте.
- Нужен Node.js: Lighthouse запускается через `npx`.

### 2. Семантика и структура

1. `chromectl navigate <url>` (или `pages new <url>`).
2. `chromectl snapshot` — роли, имена, `heading ... level="N"`.
3. **Уровни заголовков** идут подряд, без пропусков (`h1` → `h3` — ошибка).
4. **Порядок чтения**: сравни порядок узлов в снапшоте со скриншотом
   (`chromectl screenshot -o /tmp/page.png`, затем Read). Float и absolute могут
   переставить визуальный порядок относительно DOM.

### 3. Подписи, формы, альтернативный текст

1. Найди в снапшоте кнопки, поля и картинки.
2. У интерактивного элемента есть имя: `button ""` у кнопки-иконки — ошибка.
3. **Поля без подписи**: `chromectl eval "<сниппет «Поля без подписи»>"`.
4. У картинок есть `alt` (в снапшоте — имя у `img`/`image`).

### 4. Фокус и клавиатура

1. `chromectl press Tab` (или `Shift+Tab`) — перевести фокус.
2. `chromectl snapshot` — элемент с `focusable focused` получил фокус.
3. Фокус переходит по ожидаемым интерактивным элементам; открылось модальное окно —
   фокус внутри него и не выходит, пока окно не закрыто.

### 5. Размер области нажатия

По web.dev область нажатия не меньше 48×48 px с отступами. Размеров в дереве
доступности нет — измерь элемент:

```bash
chromectl eval "<сниппет «Размер области нажатия»>" --arg <uid>
```

### 6. Контраст

Сообщений типа `issue` из панели Issues DevTools в `chromectl console` нет, поэтому:

1. Проверь аудит `color-contrast` в отчёте Lighthouse (шаг 1).
2. Для конкретного элемента — `chromectl eval "<сниппет «Контраст»>" --arg <uid>`:
   нужно не меньше 4.5:1 для обычного текста и 3:1 для крупного (WCAG AA).

### 7. Настройки документа

`chromectl eval "<сниппет «Настройки документа»>"` — `lang`, `title`, `viewport`,
`prefers-reduced-motion`.

## Если что-то не определяется

- **Контраст на градиенте или картинке** скрипт не посчитает — сними
  `chromectl screenshot --uid <uid> -o /tmp/el.png` и оцени читаемость визуально
  (точное отношение по изображению не измерить).
- **Эмуляция условий**: `chromectl emulate --color-scheme dark` — проверить тёмную
  тему; `--viewport 390x844x3,mobile,touch` — мобильную раскладку и области нажатия.
